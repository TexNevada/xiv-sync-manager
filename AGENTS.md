# Repository instructions

## Protect master

- All changes targeting `master` must go through a pull request.
- Never push commits directly to `master`, including force pushes.
- Never merge another branch or a pull request into `master`. Leave pull requests open for human review, approval, and merging.
- Continue development on `dev` or a dedicated working branch. Commit and push there when requested or already authorized.
- Installer-feed updates and release-automation changes must follow the same pull-request requirement for `master`.

This records the repository owner's instruction from 2026-10-09 and applies to future agent sessions.
