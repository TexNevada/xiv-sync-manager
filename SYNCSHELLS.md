# Native syncshell contracts

Source inspection, not an in-game compatibility claim. The manager uses the loaded plugin's own membership and permission state. It never contacts a sync server directly, creates a membership cache, or substitutes per-player actions.

All permissions shown are the current user's native shell settings, not admin defaults or a prediction of effective per-member behavior. Every write preserves all other bits from the latest native shell state. Lightless uses its ready connection session; Snowcloak waits for native reconciliation when the client exposes that signal. PlayerSync and older Snowcloak versions read the current mask through their native `GroupsGetAll` endpoint on click rather than writing from a registry that may be stale after reconnect. That read is not cached and a changed connection aborts the action. A successful transport task alone is not confirmation: the manager waits for provider readback. The native profile viewer remains responsible for fetching and reporting inaccessible content.

## Member controls and recovery

Expanded shells read native `GroupPairs` membership, including offline members. Each row retains the native UID and pair instance; its controls resolve only a matching current coordinator route from the same provider. Names are display-only, never action targets. Missing current routes remain visible but unavailable.

Member controls are separate from shell settings. Pause/resume uses manager-owned restoration, retaining unrelated permission bits and external choices. Existing native/other-player pauses are not silently overridden; global character pauses must be resumed at character level first. Sound, VFX and Animations show individual native preferences, with yellow Off and green On. Profiles use native viewers. Reload last data invokes the supported provider's forced cached-data method for nearby, online, unpaused users; it is not a fresh server download.

Cycle pause is available for online, unpaused, unmanaged routes. It uses the native `UserSetPairPermissions` pause and resume endpoints in the same order as the native menu, but both stages pass through the manager's durable ownership and confirmation pipeline. It deliberately does not call older PlayerSync/Snowcloak cycle helpers, which return a completed task while their background permission writes can still run. The first request must settle and its pause be observed before resume; other operations remain excluded until restoration completes. Interrupted cycles restore on reload instead of starting another cycle. Snowcloak cycles use native permissions, not its manager-local holds.

Failed character pause/restoration requests retry three times at 30-second intervals, then every five minutes while still desired. Pending requests are never duplicated. Native choices remain preserved rather than being reset by retry. Shell settings and reload/cycle button clicks are not automatically replayed.

## In-game acceptance checklist

- Check compact rows at the default window size and with a long shell name. Service shows Lightless, Snowcloak, or PlayerSync; Syncshells shows the shell name. The left arrow expands the provider's native `GroupPairs` roster by GID beneath the shell name (Lightless exposes it on its collection view). Compare against the native list with all members offline. Check empty and unavailable rosters, including shells with the same display name. Member lists are read only for expanded, visible shells; aliases fall back to native UIDs.
- Check that Pause and Resume use the native-style pause and play icons, unsupported pause shows `N/A`, and each media control stays on the same line while pending. Confirm the app's amber/yellow treatment for Off and green for On, including in the PaperAndInk theme.
- With all three loaded, compare joined shells against the native menus, including an empty shell and same-named shells. Toggle each provider and confirm only its rows hide. Turn off automatic duplicate management and repeat.
- In each provider, cancel the shell pause confirmation and verify nothing changes; then confirm pause and resume with zero nearby members and with all members offline. Confirm both directions in native menus. For PlayerSync, verify non-sticky pause reasons change and manager-owned pair pauses remain restorable. Repeat with automatic management Off.
- For each provider, change one media setting at a time. Check the corresponding native setting, the other two flags, and any unrelated individual pair permissions. Change it back in the native menu and verify the manager refreshes.
- Open each supported native profile, including two same-named shells in succession. Test a hidden/unavailable profile in the native viewer. Check that Snowcloak's disabled `N/A` profile button matches the size of `Open` and explains why on hover.
- Disconnect or unload one provider while keeping the other two loaded. Check list and action status before and after reconnect; no request should replay. Reload the manager and verify it reads shell settings from the plugins again.
- Compare all Nearby, Online and Offline users with native lists, including accounts never identified as duplicates. Check same aliases/UIDs across providers remain distinct until character identity is verified.
- Expand both character routes and shell rosters. Check pause/media controls, profiles, reload and cycle buttons. Verify disabled controls explain offline, existing pause and pending states. Check long names, horizontal scrolling and amber/green media states.
- Cycle an active route, then reload the manager between its two stages. Verify the interrupted pause restores and never restarts a cycle. Test a slow native request: it must remain excluded from conflicting operations, not time out into a second request.
